## 4. Recipe Selection

**Selected:** AZCLI

**Rationale:**

- The application is a static GitHub Pages site, not an AZD-managed Azure host.
- The repository already contains `scripts/setup.ps1` with the required workspace-based free-tier setup.
- Direct Azure CLI is the smallest and most transparent change for a resource group, Log Analytics workspace, Application Insights component, and Portal dashboard.
- `azure/dashboard.json` remains the declarative dashboard artifact; no new Bicep or Terraform stack is necessary.

---

## 5. Architecture

**Stack:** Static site with external observability

### Service Mapping

| Component | Azure Service | SKU / settings |
|-----------|---------------|----------------|
| Telemetry workspace | Log Analytics | `PerGB2018`, 30-day retention, `0.16 GB/day` cap |
| Application Insights | Workspace-based `Microsoft.Insights/components` | `web`, application type `web`, 30-day retention via workspace |
| Portal dashboard | `Microsoft.Portal/dashboards` | `apm-book-dashboard`; no metered ingestion |

### Supporting Services

No Key Vault, managed identity, database, storage, or Azure-hosted compute is required for this static site. The connection string is a public, write-only client key and is stored only as a GitHub repository variable for build-time injection.

### Instrumentation

- `analytics/entry.js` initializes one in-memory beacon client per page load with automatic page views.
- Delegated events cover shared/deep links, code-copy actions, sidebar toggles, orchestration controls, anchors, internal navigation, outbound links, and debounced input changes.
- `site/generate.py` emits the ignored `site/assets/analytics-config.js` at build time.
- CI passes `vars.APPINSIGHTS_CONNECTION_STRING` to both site and release builds.
- Missing configuration remains a deliberate no-op; the live deployment now uses the repaired variable.
